# Technical SEO checks on JavaScript-rendered snapshots (desktop and mobile)

Date: 2026-09-14. Scope: checks the Electron offscreen renderer can run on a settled page, per device, that a raw-HTML crawl cannot see. Speed and Core Web Vitals timings are out of scope (Lighthouse later).

Renderer facts assumed throughout: desktop 1366x900 with a Googlebot UA; mobile 412x915 at DPR 2.625, touch emulation, Googlebot smartphone UA; waits for network idle; captures rendered HTML, the Chrome debugger network log (every request with type, status, bytes), runtime exceptions and console messages; can run an in-page script after settle. "Raw" below always means the HTML the static crawler fetched for the same URL.

## 1. What rendered analysis sees that raw HTML cannot

Google indexes what its Web Rendering Service produces after executing JavaScript in evergreen Chromium, in a separate rendering phase queued after the raw crawl ("Google Search runs JavaScript with an evergreen version of Chromium"; "the initial HTML does not contain the actual content and Google needs to execute JavaScript before being able to see the actual page content" - https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics). A raw fetch therefore cannot know: whether the DOM that Google will index is populated at all or is still an app shell; whether JavaScript added, changed, duplicated or deleted the title, description, canonical, robots directives, headings, JSON-LD, hreflang or links; whether the page navigated somewhere else (History API, `window.location`, meta refresh injected by script); whether the subresources needed to build that DOM actually loaded (robots.txt blocks, 4xx/5xx, CORS, network errors, unsupported WebSocket/WebRTC), and what breaking exceptions the scripts threw along the way; and, on a phone-sized viewport with touch emulation, what the mobile layout actually does to text, tap targets, overflow, overlays and hidden content - the things the retired Mobile Usability report and Lighthouse's SEO audits measured on a rendered layout, and the parity rules Google's mobile-first indexing guidance requires ("Make sure that your mobile site contains the same content as your desktop site" - https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing). Practitioner crawlers frame all of this as a response-vs-render diff (Sitebulb's Response vs Render report classifies each SEO element as No Change / Created / Modified / Duplicated / Deleted - https://support.sitebulb.com/en/articles/9857330-response-vs-render-report; Screaming Frog's JavaScript issue catalogue - https://www.screamingfrog.co.uk/seo-spider/issues/javascript/; Botify's rendered-vs-raw comparison - https://www.botify.com/blog/javascript-seo-analysis-tool), plus the two things only a real browser produces: a console and a network log.

## 3. Ranked shortlist of NEW checks to implement

Ranking is by (severity, confidence of detection, cost). Every rule below runs per device unless marked cross-device; cross-device rules run once per URL after both renders exist. All "raw" comparisons normalise whitespace, decode entities, resolve hrefs against the final URL, strip trailing slashes and drop `utm_*` before comparing.

### (a) JavaScript dependency and indexability

1. **soft-404-after-render** (p0, both). Inputs: main-document status, rendered title, h1s, visible word count, rendered internal link count, rendered robots. Fire when status is 200 AND (`title` or any `h1` matches `/\b(404|not found|page (doesn't|does not|cannot be) (exist|found)|no longer available|oops)\b/i`) AND (word count < 150 OR internal links outside `nav/header/footer` == 0) AND rendered robots does not contain `noindex`. Do not fire if the raw HTML already matched the regex (static soft-404 rule owns that). Message names the fix Google gives: redirect to a URL that returns 404 or inject noindex.
2. **rendered-body-empty** (p0, both). Fire when main-document status is 200, rendered visible word count < 30, and no h1, regardless of raw. Visible word count = words in text nodes whose ancestor chain has no `display:none`/`visibility:hidden` and whose element has non-zero bounding box. Attach the exception list and failed first-party requests as evidence.
3. **render-exception-with-thin-content** (p0, both). Fire when >= 1 uncaught runtime exception was recorded AND (rendered word count < raw word count OR rendered word count < 100). Evidence: first three exception messages with script URL. Suppress plain console-errors on the same page to avoid double-reporting.
4. **content-lost-after-render** (p1, both). rendered word count < 0.7 x raw word count AND raw - rendered >= 100. Evidence: the first 200 characters of raw text absent from rendered text (computed by splitting raw text into sentences and testing `rendered.includes`).
5. **links-lost-after-render** (p1, both). `lost = rawInternal - renderedInternal` after normalisation; fire when `|lost| >= 5` OR `|lost| >= 0.2 x |rawInternal|`. Evidence: up to 10 lost URLs.
6. **uncrawlable-anchors-after-render** (p1, both). In-page script collects: `a` without `href` that have an `onclick` attribute or `role`; `a[href=""]`, `a[href="#"]`, `a[href^="javascript:"]` (void patterns), `a[href^="file:"]`; non-anchor elements with `role="link"`; any `[onclick]` whose handler text matches `/location\.(href|assign|replace)|router\.(push|navigate)|history\.pushState/`. Exempt `mailto:`, `tel:`, anchors with `id` and no `href`. Fire at >= 3 per page, or >= 1 inside `nav`, `header`, `footer`, or `[role=navigation]`. Report only those not present in raw (raw ones belong to the static crawler).
7. **fragment-navigation-links** (p1/p2, both). For each internal rendered `a[href]`: if href contains `#!` -> p1 (old-ajax-crawling-scheme); if `meta[name=fragment]` exists -> p1; else if path+query equals the page's and fragment is non-empty and `document.getElementById(decodeURIComponent(fragment))` is null and no `[name=fragment]` anchor exists -> count as dangling; fire p2 at >= 5 dangling.
8. **url-changed-by-history-api** (p1, both). After settle, compare `new URL(location.href)` (hash dropped) with the requested URL after redirects recorded in the log. If different and no main-frame navigation occurred, fire. If the existing client-side-redirect rule is navigation-based, add this as its `history` sub-kind rather than a new rule.
9. **interaction-gated-content** (p2, both). Fire when a visible `button`, `a`, or `[role=button]` has text matching `/^(load|show|view|see) more/i` AND the page has no `a[href]` matching `/[?&]page=\d+|\/page\/\d+/` AND no `link[rel=next]`. Skip when the control is inside a `form`.
10. **images-without-src-after-render** (p1, both). In-page: for each `img` in the rendered DOM with non-zero bounding box: flag if `!getAttribute('src')` OR `src` starts with `data:` and `naturalWidth <= 1` OR (`dataset.src || dataset.lazy || dataset.original`) exists and `currentSrc` is empty. Fire at >= 1 whose top < viewport height, else at >= 25% of images.
11. **shadow-dom-content-unslotted** (p2, both). In-page: walk all elements; for each with `shadowRoot`, count words in `shadowRoot.textContent` minus words of its light-DOM children that are assigned to a `slot`. Fire at >= 200 words. Also switch the HTML capture to `document.documentElement.getHTML({serializableShadowRoots: true})` when available so word count and content hash include shadow trees; note that Google flattens shadow DOM so this is a measurement-fidelity rule first.
12. **service-worker-registered** (p3, both). `navigator.serviceWorker.getRegistrations().length >= 1`. Informational only.

### (b) Rendering health

1. **failed-data-request** (p1, both). From the debugger log: requests with `type in {XHR, Fetch}`, same registrable domain as the page (or a host that appears in the page's `link[rel=preconnect]`/`dns-prefetch`), `status >= 400` or `errorText` set, excluding beacons/analytics paths (`/collect`, `/beacon`, `/track`, `/log`). Fire at >= 1; evidence: method, URL, status.
2. **failed-first-party-script** (p1, both). Same as above with `type == Script`. Fire at >= 1.
3. **cors-blocked-request** (p1, both). Console messages matching `/blocked by CORS policy|No 'Access-Control-Allow-Origin'/i`. Fire at >= 1; evidence: the URL in the message.
4. **network-never-idle** (p2, both). Renderer reports `settleReason: 'idle' | 'timeout'` and the list of requests without a response at capture. Fire when reason is `timeout` and >= 3 requests are still pending; evidence: pending URLs and types. If the pending set is all `Ping`/`Other`/`EventSource`, downgrade to p3.
5. **unsupported-transport-used** (p2, both). Any log entry with `type == WebSocket`. Evidence: the URL and whether the page's word count is below raw (if so, raise to p1).
6. **mixed-content-requests** (p1/p3, both). Page final URL is https and a log entry's URL scheme is http. p1 when type in {Script, Stylesheet, XHR, Fetch, Document}, p3 for Image/Media/Font.
7. **resource-over-2mb** (p0/p1, both) and **rendered-html-over-2mb** (p1, both). From the log, decoded body size or `encodedDataLength` > 2,097,152 for the main document (p0) or any Script/Stylesheet (p1). Rendered HTML length > 2 MB (p1). Evidence: URL and bytes.

### (c) Mobile usability and parity

1. **mobile-status-differs-from-desktop** (p0) and **mobile-final-url-differs-from-desktop** (p1), cross-device. Compare main-frame final status and final URL (hash dropped) between the two device logs. Also fire the URL rule when only one device redirected.
2. **viewport-meta-invalid** (p1/p2, mobile). Parse rendered `meta[name=viewport]` content into key/values. p1 when absent or lacking `width=`; p2 when `initial-scale < 1`, `user-scalable=no|0`, or `maximum-scale < 1`. Also record the parsed value per device.
3. **viewport-meta-changed-by-js** (p2, mobile). Raw vs rendered content string differs after key sort.
4. **mobile-intrusive-overlay** (p1 mobile, p2 desktop). In-page after settle: for each element with computed `position` in {fixed, sticky, absolute}, opacity > 0.05, `visibility != hidden`, and bounding rect intersecting the viewport: area of intersection / viewport area >= 0.5 -> candidate; confirm with `document.elementFromPoint(innerWidth/2, innerHeight/2)` being the candidate or a descendant. Exclude candidates whose only text is < 15 words and that contain a single dismiss button smaller than 48 px (small banners are permitted). Evidence: tag, id/class, coverage %, first 100 chars of text.
5. **mobile-illegible-text** (p2, mobile). TreeWalker over visible text nodes; for each, `len = textContent.trim().length`, `size = parseFloat(getComputedStyle(parentElement).fontSize)`; `small += len` when size < 12. Fire when `small / total >= 0.4` and `total >= 200` characters. Report the top three selectors by small-character count.
6. **mobile-word-count-drop** (p1, cross-device). mobile visible word count < 0.8 x desktop AND delta >= 100. Runs on visible words (not display:none), so it complements the existing hidden-content rule which measures words present but hidden.
7. **mobile-description-differs-from-desktop** (p1) and **mobile-h1-differs-from-desktop** (p2), cross-device. Normalised string inequality.
8. **mobile-schema-differs-from-desktop** (p1, cross-device). Sorted @type multiset differs, or any block hash present on desktop is absent on mobile.
9. **mobile-image-alt-differs** (p3, cross-device). Build `src -> alt` per device for `img` with non-empty `src`; fire on any key present in both with different alt, or present on desktop with alt and on mobile without.

### (d) Page weight and resource hygiene (no timings)

1. **resource-over-2mb** and **rendered-html-over-2mb** - see (b)7; the 2 MB rule is Google's documented crawl limit, not a performance heuristic.
2. **mixed-content-requests** - see (b)6.
3. No further weight rules are proposed: JS bytes, total bytes, request count and third-party hosts are already stored, and other resource-hygiene audits (unused JS, image sizing, caching) are Lighthouse territory with timing or coverage inputs.

### (e) Structured data and metadata after render

1. **schema-changed-by-js** (p1, both). Parse every rendered `script[type="application/ld+json"]`, flatten `@graph`, collect `@type` values (arrays expanded) and a stable hash per block (JSON with sorted keys). Compare with raw: fire when any raw @type is missing from rendered ("deleted"), when the same @type appears in >= 2 blocks with different hashes ("duplicated"), or when the set is equal but hashes differ ("modified", p2). schema-only-after-js stays as it is.
2. **schema-invalid-after-render** (p1, both). Any block where `JSON.parse` throws. Evidence: script index and the first 120 characters.
3. **canonical-duplicated-after-render** (p0/p2, both). `link[rel=canonical]` count >= 2: p0 when distinct resolved hrefs, p2 when identical.
4. **canonical-invalid-after-render** (p1, both). Rendered canonical fails `new URL(href)` without a base, or resolves to `/` while the page path is not `/`, and the raw canonical did not have the same defect.
5. **robots-directives-conflict-after-render** (p1, both). Collect all `meta[name=robots]` and `meta[name=googlebot]`; fire when count >= 2 OR the union contains both a positive (`index`, `follow`, `all`) and a negative (`noindex`, `nofollow`, `none`) directive. Evidence: each tag's content in document order, and whether it was in raw.
6. **nofollow-changed-by-js** (p1, both). Presence of `nofollow`/`none` in rendered robots directives differs from raw.
7. **title-modified-by-js** (p1), **meta-description-modified-by-js** (p2), **h1-modified-by-js** (p2), both. Present in both raw and rendered, normalised text differs. For h1, compare ordered list of h1 texts.
8. **meta-description-only-after-js** (p2, both). Absent raw, present rendered.
9. **title-duplicated-after-render** and **description-duplicated-after-render** (p2, both). Element count >= 2 in rendered document.
10. **hreflang-changed-by-js** and **hreflang-invalid-after-render** (p2, both). Set of `(hreflang, href)` pairs from rendered head differs from raw; or any rendered href not starting with `http:`/`https:`; or language subtag (before `-`) not a valid ISO 639 code and not `x-default`.
11. **og-tags-only-after-js** (p2, both). `meta[property^="og:"]` or `meta[name^="twitter:"]` absent raw, present rendered.
12. **data-nosnippet-changed-by-js** (p2, both). `[data-nosnippet]` count differs raw vs rendered.
13. **unrendered-template-tokens** (p1/p2, both). Regex `/\{\{[^}]+\}\}|\{[a-zA-Z_][\w.]*\}|\[\[[^\]]+\]\]/` over rendered title, description, h1s (p1 on any match) and visible body text (p2 at >= 3 matches).

### (f) Links and navigation after render

1. **uncrawlable-anchors-after-render** - see (a)6.
2. **links-lost-after-render** - see (a)5.
3. **fragment-navigation-links** / **old-ajax-crawling-scheme** - see (a)7.
4. **js-injected-images-missing-alt** (p2, both). Rendered `img` set minus raw `img` set (by resolved src); fire when any of the remainder lacks an `alt` attribute (empty `alt=""` and `role="presentation"` are exempt, per the Lighthouse image-alt audit).
5. **external-links-injected-by-js** (p3, both). External hrefs in rendered not in raw; fire at >= 5; evidence: hosts and counts.
6. **plugin-content-after-render** (p3, both). Rendered `embed, object, applet` with `type` in the Lighthouse list (`application/x-shockwave-flash`, `application/x-silverlight*`, `application/x-java-*`) or `src`/`data` ending in `.swf`, `.flv`, `.class`, `.xap`, not present in raw.

## 4. Checks considered and rejected

| Check | Reason |
|---|---|
| Core Web Vitals (LCP, INP, CLS), FCP, TBT, Speed Index, render-blocking resources, long tasks | Out of scope by instruction; timing-based and single-machine; Lighthouse later. |
| Unused JavaScript / CSS coverage (Screaming Frog "Reduce unused JavaScript" via PSI) | Needs CDP coverage profiling and is a performance audit, not an indexability one; Lighthouse will supply it. |
| DOM size (element count / depth) | Lighthouse performance audit; no Google Search documentation ties it to indexing; noisy per template. |
| Oversized or unoptimised images (bytes per image, missing srcset) | Performance/Lighthouse; Google's mobile-first only says "provide high quality images", which cannot be measured as a threshold. |
| Page requires user permissions at load (geolocation, camera, notifications) | Google says Googlebot declines permission requests, but detecting the request needs a pre-load hook on `navigator.permissions`/`geolocation`/`Notification` before scripts run; our script runs after settle. Revisit if the renderer gains a preload script. |
| WebRTC usage | Same reason: `RTCPeerConnection` construction cannot be observed after the fact; WebSocket is kept because it appears in the network log. |
| Content depending on localStorage / sessionStorage / cookies across loads | Google clears storage between loads, but a single render cannot tell whether the page *depended* on stored state; would need a second render with storage cleared and a diff. Too speculative for one snapshot. |
| Cloaking check (Googlebot UA render vs normal UA render differ) | Needs a third render per page per device; Google's dynamic-rendering doc says similar content is fine, so a threshold would be arbitrary. Candidate for a later, opt-in site-level audit. |
| Content truly loaded on scroll / infinite scroll actually working | Requires interaction; Google does not interact, so the proxy rule interaction-gated-content is kept and the simulated scroll is rejected. |
| Aggressive caching / missing content fingerprinting of JS bundles | Google's advice (fingerprinted filenames) is a build practice; a heuristic on filenames (hash present or not) is too noisy and there is no per-page indexing consequence we can evidence. |
| Generic link text ("click here", "learn more") after render | Lighthouse link-text is static-DOM; duplicates the static crawl rule unless links were JS-injected, and that subset is not worth a separate rule. |
| Missing title / missing description / missing h1 after render | If missing in both raw and rendered the static rule owns it; if present only after JS the existing only-after-js rules own it. Nothing new to add. |
| robots.txt validity, X-Robots-Tag noindex header, 4xx/5xx main-document status | Response-header and static checks already available to the raw crawler; the render adds nothing. Only the cross-device status parity rule is kept. |
| Hidden tabbed/accordion content on mobile | Existing mobile-hidden-content rule already measures display:none words; Google's mobile-first guidance treats tabbed content as acceptable, so a stricter rule would generate false positives. |
| Tap targets, viewport overflow, hidden links, title/canonical/noindex parity, JS-only content on mobile | Already implemented. |
| Text too small measured on desktop | The retired GSC report and Lighthouse only measured it on the mobile form factor. |
| Meta refresh injected by JS | Already covered by client-side-redirect (navigation-based). |
| Video placement "easy to find on mobile" | Not measurable as a threshold from Google's wording. |
| Better Ads Standard / excessive ads above the fold | Needs ad-slot classification and layout heuristics that Google does not document as thresholds; too noisy. |
| Service worker as an error (rather than informational) | Google's own doc set fetched here does not state SW is disabled; only a practitioner source does, so it stays p3. |
